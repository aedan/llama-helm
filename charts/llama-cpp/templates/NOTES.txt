  1. Label nodes to receive llama.cpp pods
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  kubectl label node <node-name> llama.cpp=enabled

  The RPC DaemonSet will schedule a worker on every labelled node.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  2. Model management
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Add models to the library in values.yaml, then helm upgrade:

    models:
      active: "my-model.gguf"          # which file to serve
      library:
        - name: my-model
          filename: my-model.gguf
          url: "https://huggingface.co/..."

  The model-loader Job downloads any new entries to the PVC.
  Files already present are skipped (idempotent).

  For gated / private HuggingFace models, create the token secret first:

    kubectl create secret generic {{ include "llama-cpp.secretName" . }} \
      --namespace {{ .Release.Namespace }} \
      --from-literal=HF_TOKEN='hf_...'

  Switch the active model without re-downloading:

    helm upgrade {{ .Release.Name }} <chart> --set models.active=other-model.gguf

    curl http://localhost:8080/v1/chat/completions \

  Enable the Gateway route:
    --set gateway.enabled=true \

  Architecture: multi-node RPC tensor split
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌─────────────────────────────────────────────────────────┐
  │  coordinator pod (llama-server)                         │
  │  - waits for active model on PVC, then starts server    │
  │  - connects to all rpc-worker pods at startup           │
  └──────────┬──────────────────────────────────────────────┘
             │  --rpc worker1:50052,worker2:50052,...
  ┌──────────▼──────────┐   ┌────────────────────────┐
  │  rpc-worker (node1) │   │  rpc-worker (node2)    │  ...
  │  rpc-server         │   │  rpc-server            │
  └─────────────────────┘   └────────────────────────┘
             ↑
  model-loader Job writes GGUF files to shared PVC
